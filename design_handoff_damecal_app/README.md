# 引継ぎ: ダメ計アプリ — Liquid Glass iPhone

## Overview
ポケモンSV / Champions 向けのダメージ計算 iOS アプリのデザインリファレンス。
Apple の **Liquid Glass** デザイン言語をベースにした iPhone 用 3 タブ構成（ダメ計 / パーティ / 履歴）。
**Light テーマ + Dark テーマの 2 種類**を含み、それぞれ異なる背景アートでガラスの透過感を活かす。

## About the Design Files
このフォルダに同梱されている `damecal-app.html` および `*.jsx` は **HTML で作成されたデザインリファレンス**であり、実装意図された見た目と挙動を示すプロトタイプです。**そのまま本番コードとして使うものではありません**。

実装タスクは、これらのデザインを **対象コードベースの既存環境**（SwiftUI / React Native / Flutter など）に **そのフレームワークの確立されたパターンとライブラリを使って再現すること** です。コードベースが未着手の場合は、プロジェクトに最も適切なフレームワークを選んで実装してください。

iOS の Liquid Glass を本格的にやるなら **SwiftUI（iOS 26+）** が第一候補で、`.glassEffect()` モディファイアと `Glass` マテリアルが使えます。React Native の場合は `expo-blur` + `BlurView` で `iOSのsystemUltraThinMaterial` 相当を擬似再現する形になります。

## Fidelity
**High-fidelity (hifi)**。色・タイポグラフィ・スペーシング・装飾レイヤー（blur量、リム、内側ハイライト）まで意図的に決定済み。**ピクセルパーフェクトに再現すること**。

ただし以下はプレースホルダなので実データで置換が必要：
- ポケモン画像（現状はテキストのみ）
- アイコン（タブバーのみ自前 SVG。それ以外は最小限）
- ダメ計の数値（サンプルデータ）

## Design System

### テーマ
2 つのテーマを切り替え可能。`ThemeCtx`（React の Context）で配信し、`useTheme()` フックで取得。
- **dark** — 夜景・オーロラ調。背景はラジアルグラデーションで青紫〜深緑〜紫オレンジ。
- **light** — 春霞・パステル調。背景は淡い水色〜ピンク〜クリーム。

`damecal-app.html` 内の `TH` オブジェクトに **すべてのデザイントークンが定義済み**。実装時はこれをそのまま enum / theme オブジェクトに移植すること。

### Liquid Glass の構造（最重要）
すべてのガラスパネル / ボタン / タブバーは **3 層構造**：

1. **Tint + Blur 層** — 半透明の色層 + `backdrop-filter: blur(28px) saturate(190%)`
   - dark: `rgba(34,30,55,0.4)` 系
   - light: `rgba(255,255,255,0.55)` 系
2. **Sheen 層** — 上から下への白いハイライトグラデーション
   - dark: 上 32% → 下 4%
   - light: 上 70% → 下 5%
3. **Rim 層** — 内側 0.5px の細いボーダー + 上端 1px の白いハイライト
   - dark: rim `rgba(255,255,255,0.18)`、上端 `rgba(255,255,255,0.22)`
   - light: rim `rgba(255,255,255,0.95)`、上端 `rgba(255,255,255,0.85)`

**この 3 層構造を 1 つでも省略すると Liquid Glass の質感が出ない**。SwiftUI なら `.background(.ultraThinMaterial)` + 上から `LinearGradient` overlay + `.overlay(RoundedRectangle().stroke(...))` の組み合わせで再現する。

## Screens

### 1. ダメ計（Calculator）画面

#### Layout
スクロール可能。上から：
1. **ヘッダ** — "POKÉMON CHAMPIONS" / "ダメ計"
2. **パーティ選択ガラス** — 自分（攻撃チップ列）+ 相手（防御チップ列）。選択中チップは accent 色塗り、未選択は半透明白。
3. **Attacker カード** — 角丸 26px の主要ガラス。中身：
   - "ATTACKER" ラベル + 名前 + ステータス数値（モノスペース）
   - タイプピル列
   - 持ち物 / 特性の **ガラス入れ子**（`glassNest`）2列グリッド
   - 攻撃 / 特攻の努力値プログレスバー（青グラデ + シャドウグロー）
4. **技ガラス** — 4 技を 2x2 グリッド。アクティブ技は `rgba(90,200,250,0.18)` の青いガラス + `rimAccent`、非アクティブは `glassChip2`。
5. **Defender カード** — Attacker と同構造、簡略版（ステータス数値 H/B/D）
6. **計算結果**（3 件）— 各カードに：
   - タイプピル + 技名 + 倍率（×1, ×0.5）
   - **ダメージ範囲**（モノスペース 16px / 800） + 実数値ロール
   - **残HPプログレスバー**（高さ 6px、6 色グラデ：残量に応じて緑→黄→赤）
   - **KO判定テキスト**（確定1発=赤 / 確定2発=黄 / 確定3発以上=白 / 乱数1発=オレンジ系）

#### KO判定の色マッピング
- 確定1発: `#FF3B30`
- 乱数1発（高確率）: `#FF6E6E`（dark） / `#c92a2a`（light）
- 乱数1発（中確率）: `#FF9F40` / `#c95a00`
- 確定2発: `#FFD460` / `#c97a00`
- 確定3発: text 色（白 / 濃紺）
- 確定4発以上: textMuted

### 2. パーティ画面

3. **使用中パーティ**（フィーチャー枠）— `glassDeep` + `rimActive` で **強調**。"使用中" バッジは青グラデのピル。中身は **6 体を 2x3 グリッド**で表示：

### 3. 履歴画面

#### Layout
1. **ヘッダ** — "RECENT CALCULATIONS" / "計算履歴" + "すべて削除" ボタン（右寄せ）

## Floating Tab Bar
すべての画面共通。**画面端から 18px 浮いた**ピル型ガラスバー。
- 高さ 60px、外殻 radius 30、blur 30、`tabTint`
- 3 タブ: ダメ計 / パーティ / 履歴
- **アクティブタブのみラベルが横展開**（flex 1.4）、内側にハイライトピル（`tabActiveBg` 線形グラデ + `tabActiveShadow`）
- 非アクティブはアイコンのみ
- アイコンはすべて自前 SVG（22x22）
- 切替アニメーション: 0.25s `cubic-bezier(0.4, 0, 0.2, 1)`

## Backdrops（タブごとに別）
各タブに専用の背景アート。**Liquid Glass の透過感はこの背景があってこそ**なので、必ず実装すること。

### Dark
- **ダメ計**: 紫青ベース + 青/赤/緑のラジアルグロー + ★（白いドット 40 個）
- **パーティ**: 深い青緑ベース + ティール/紫/青のラジアル
- **履歴**: 深い紫オレンジベース + オレンジ/紫/ピンクのラジアル

### Light
- **ダメ計**: 水色→ラベンダー→桜色のリニア + 水色/桃/緑のラジアル
- **パーティ**: 水色→淡いティール→クリームのリニア + 水色/紫/オレンジのラジアル
- **履歴**: オレンジ→藤→ライラックのリニア + オレンジ/紫/ピンクのラジアル

CSS / SwiftUI 実装時は **複数の `RadialGradient` を重ねる** ことで再現できる。各 stop の位置・サイズ・透明度は `BACKDROPS` 定数を参照。

## Interactions & Behavior

### タブ切替
- ボトムタブをタップで `active` ステート更新
- アクティブタブが flex 1.4 に拡大、ラベルがフェードイン
- 画面コンテンツは即座に差し替え（フェードトランジションを足してもよい）

### スクロール
- 各画面はメインコンテンツ縦スクロール
- タブバーは fixed、スクロールしてもボトムから 26px の位置に常駐

### ステート管理
- アクティブタブ
- 攻撃側 / 防御側の選択中ポケモン
- 各ポケモンの努力値・持ち物・特性・技構成
- 計算結果は選択された技ぶん配列で持つ
- パーティ画面の使用中パーティ ID
- 履歴は配列で永続化（CoreData / SQLite / AsyncStorage）

### 計算ロジック
ダメ計本体のロジックはこの引継ぎ範囲外（既存の damage-calc ライブラリを使うのが普通）。UI は **計算結果オブジェクト** を受け取って描画するだけ。

## Files
- `damecal-app.html` — メインの React プロトタイプ。**6 アートボード**（dark/light × calc/party/history）が design canvas 上に並ぶ。
- `design-canvas.jsx` — アートボード並列表示用ヘルパー（実装時は不要、リファレンスとして同梱）
- `ios-frame.jsx` — iPhone デバイスフレーム（実装時は不要、リファレンスとして同梱）

## 実装優先順位の提案
1. **ガラス primitive（`Glass` / `GlassLayers`）を最初に作る** — これが全画面の土台
2. **テーマシステム** — `TH` オブジェクトを enum / theme provider に移植
3. **Backdrop コンポーネント** — タブごとのラジアルグラデ背景
4. **TabBar** — フローティング、アクティブピル展開
5. **画面 1（ダメ計）** — もっとも要素が多い、ここをこなせば他は派生
6. **画面 2（パーティ）→ 画面 3（履歴）**
7. **ライトモード対応** — Dark で全部組んでから theme フックでライトに切替

## 注意点
- `backdrop-filter` は iOS Safari / WebKit では動くが、SwiftUI は `.background(.regularMaterial)` などのマテリアルを使う方が綺麗
- ガラスの内側 sheen は **必須**。これがないと「ただの半透明パネル」になる
- タイプピルの `boxShadow` の `inset 0 1px 0 rgba(255,255,255,0.4)` は質感のキモなので省略しないこと
- 数値はすべて `SF Mono` 等幅で揃える
- 日本語フォントは Noto Sans JP がフォールバック。iOS なら標準のヒラギノでよい
